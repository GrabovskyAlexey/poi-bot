# Бэклог идей и улучшений

Идеи, собранные во время разработки MVP (этапы 0–4 из `docs/ROADMAP.md` закрыты). План работ по ним составляем **после успешного деплоя MVP**: каждую задачу оформляем отдельной папкой миграций в `src/main/resources/liquibase/<задача>/` (см. `AGENTS.md`).

Размер: **S** — часть дня, **M** — день–два, **L** — несколько дней.

## 1. Хвосты MVP
| Идея | Размер | Комментарий |
|---|---|---|
| Ручная проверка группового сценария: публикация, `/places` и `/nearby` в группе, снятие админом, обычным участником | S | Единственный пункт чеклиста этапа 2, не прогнанный вживую |
| Обновлять карточку после «✏️ Изменить» | S | Сейчас карточка остаётся старой (оценки и комментарии уже обновляют её через `EditCardAction`) |
| Удалять сообщения-команды (`/add`, `/places`…) в личке | S | `AbstractCommand` не знает id сообщения команды; бот может удалять сообщения пользователя в личке |
| Убирать reply-клавиатуру «📍 Отправить геопозицию» после `/nearby` | S | Сейчас висит постоянно (есть `FlowMessage.removeReplyKeyboard`) |
| Не дублировать в группе одно место, опубликованное двумя участниками | M | Группировка по `place_id` в `/places` и `/nearby` группы |
| Резерв: проверка членства в группе работает полноценно только если бот админ | S | Описать в справке/подсказке при добавлении бота |

## 2. UX
| Идея | Размер | Комментарий |
|---|---|---|
| Поиск по названию в `/places` | M | `ILIKE` по названию/адресу |
| Сортировка списка: новые / ближайшие / по рейтингу; фильтры «с геопозицией», «с фото» | M | Рейтинг одним запросом на страницу |
| ⭐ рейтинг в строке списка | S | Пакетный запрос `avg/count` по `place_id` страницы |
| Теги и категории (бар, кафе, ресторан, кофейня + свои), фильтр в списке и в `/nearby` | M | Исходная идея про типы заведений |
| Отметки «был / хочу сходить» и личная заметка | M | Рейтинг общий, статус и заметка — личные |
| `/settings`: язык, радиус по умолчанию, поведение временных сообщений | S–M | Поле `locale` в профиле уже есть, интерфейса нет |
| Присланная боту геопозиция «просто так» → предложение найти места рядом | S | Реакция вне активного flow |
| Несколько фото у места | M | Сейчас одно фото (`file_id`) |
| Импорт из ссылок на карты (Google/Яндекс): название и координаты | M | Парсинг ссылки, id организации как сильный ключ склейки мест |

## 3. Шаринг и соцчасть
| Идея | Размер | Комментарий |
|---|---|---|
| Inline-режим: пересылка красивой карточки места в любой чат | M | Нужно включить inline в @BotFather и обрабатывать inline-запросы |
| Отзыв ссылки-приглашения и срок действия | S | Сейчас одна вечная ссылка на место |
| Искать в `/nearby` также места групп, где пользователь состоит | M | Через `user_chat` и `saved_place_chat` |
| Рейтинг места в списке группы и сортировка по нему | S | |
| Live Location: «рядом с вами сохранённое место» | L | Пользователь делится живой геопозицией с ботом; есть нюансы приватности |

## 4. Эксплуатация и безопасность
| Идея | Размер | Комментарий |
|---|---|---|
| `/deleteme` и выгрузка своих данных | M | Почти обязательно для публичного бота |
| Лимиты частоты команд и комментариев (антиспам) | M | Сейчас только лимит 500 мест на пользователя |
| Админ-панель: статистика, скрытые комментарии, блокировки | L | Сейчас модерация только через жалобы (3 жалобы → скрытие) и удаление автором |
| Экспорт метрик (Prometheus), дашборд по `poi.place.resolve.*` | S | Метрики есть, но actuator экспортирует не всё |
| Автоматические бэкапы БД и проверка восстановления | M | Первичная инструкция — `docs/DEPLOY.md` |
| Webhook вместо long polling | M | Нужен публичный HTTPS; позволяет масштабировать на несколько экземпляров |
| Другие языки интерфейса (кроме ru/en) | M | Сейчас `messages_*.properties` и `*_en.ftl` |
| Вычитка текстов и шаблонов целиком (тон, опечатки) | S | Первая вычитка сделана в этапе 4 |
